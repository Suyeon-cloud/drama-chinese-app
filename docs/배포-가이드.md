# 배포 가이드 — GitHub → Railway, Google 로그인 설정

이 문서는 터미널 없이 웹 화면만으로 앱을 배포하는 순서입니다. 처음 한 번만 하면 되고,
이후에는 GitHub main 브랜치에 커밋(푸시)할 때마다 Railway가 자동으로 다시 배포합니다.

> 화면이 이 문서와 조금 다르거나 오류가 나면, **화면을 캡처해서 AI(Claude)에게 “이 화면에서 다음에 뭘 눌러야 해?”라고 물어보세요.**
> 오류 문구는 그대로 복사해 붙여 넣으면 더 정확하게 알려 줍니다.

---

## 1. GitHub 저장소 확인

1. https://github.com 에 로그인합니다. (계정이 없으면 회원가입)
2. 앱 저장소(예: `Suyeon-cloud/drama-chinese-app`)에 코드가 올라가 있는지 확인합니다.
   - 새로 만든다면: 오른쪽 위 **+ → New repository** → 이름 입력 → **Create repository** → 저장소 주소(링크)를 복사해 Claude 데스크탑(GitHub 연결)에 “이 저장소에 커밋(푸시)해줘”라고 요청합니다.
3. `.env` 파일은 저장소에 올리지 않습니다. 비밀 값은 아래 Railway **Variables**에 넣습니다.

## 2. Railway에 배포

1. https://railway.com 에 GitHub 계정으로 로그인합니다.
2. **New Project → Deploy from GitHub repo** → 앱 저장소를 선택합니다.
   - 저장소가 목록에 없으면 **Configure GitHub App**을 눌러 Railway가 그 저장소에 접근하도록 허용합니다.
3. 서비스가 만들어지면 자동으로 빌드가 시작됩니다. (`railway.json`에 빌드·실행 명령이 들어 있어 따로 입력할 것은 없습니다)
4. 서비스의 **Variables** 탭에서 **New Variable**로 아래 값을 넣습니다.

   | 이름 | 값 |
   |---|---|
   | `ADMIN_ID` | 관리자 로그인 아이디 (예: `admin`) |
   | `ADMIN_PASSWORD` | 관리자 비밀번호 (길고 추측하기 어렵게) |
   | `DATA_DIR` | `/data` |
   | `SESSION_SECRET` | 아무 긴 임의 문자열 (예: 40자 이상 영문·숫자) |
   | `GOOGLE_CLIENT_ID` | 3단계에서 만든 클라이언트 ID (나중에 넣어도 됩니다) |

5. **Volume 연결 (데이터 보존 — 꼭 하세요)**
   - 프로젝트 화면의 빈 곳을 오른쪽 클릭하거나 **+ Create**를 눌러 **Volume**을 고릅니다.
   - 연결할 서비스로 앱 서비스를 고르고, **Mount path**를 `/data`로 입력합니다.
   - Volume이 없으면 다시 배포할 때마다 회원·학습 기록이 사라집니다.
6. 배포 상태가 **Active(초록색)** 로 바뀌면 **Settings → Networking → Generate Domain**을 누릅니다.
   - `○○○.up.railway.app` 주소가 생깁니다. 연필 아이콘으로 앞부분 이름을 바꾼 뒤 **Update**를 누를 수 있습니다.
7. 만든 주소로 접속해 화면이 뜨는지 확인합니다. 오른쪽 위 **관리자** 아이콘으로 `ADMIN_ID`/`ADMIN_PASSWORD` 로그인이 되면 성공입니다.

### 배포 오류가 났을 때
- **Deployments** 탭에서 실패한 배포를 누르고 **Build Logs / Deploy Logs**를 캡처해 AI에게 물어보세요.
- 자주 있는 원인
  - `ADMIN_ID`/`ADMIN_PASSWORD`를 넣지 않음 → 관리자 로그인 창에 “관리자 계정이 설정되지 않았어요”가 나옵니다.
  - Volume 없이 배포 → 재배포 후 회원이 사라짐 → 5번을 확인하세요.
  - Variables를 바꾼 뒤에는 Railway가 자동으로 다시 배포합니다. 1~2분 기다린 뒤 새로고침하세요.

## 3. Google 클라이언트 ID 만들기 (구글 로그인)

1. https://console.cloud.google.com 에 Google 계정으로 로그인합니다.
2. 위쪽 프로젝트 선택 → **새 프로젝트** → 이름(예: `zhuiju-app`) → **만들기**.
3. 왼쪽 메뉴 **API 및 서비스 → OAuth 동의 화면**(또는 **Google 인증 플랫폼**)으로 갑니다.
   - **시작하기** → 앱 이름(예: 追剧学汉语), 지원 이메일 입력 → 대상은 **외부** → 연락처 이메일 → 만들기.
   - **대상(Audience)** 에서 앱이 ‘테스트’ 상태라면 **테스트 사용자**에 로그인할 Google 계정들을 추가합니다. (학생 계정 포함)
4. **API 및 서비스 → 사용자 인증 정보 → + 사용자 인증 정보 만들기 → OAuth 클라이언트 ID**
   - 애플리케이션 유형: **웹 애플리케이션**
   - **승인된 JavaScript 원본**에 두 줄을 추가합니다.
     - `http://localhost:5173` (내 컴퓨터에서 실행할 때)
     - `https://○○○.up.railway.app` (2단계 6번에서 만든 Railway 주소, 끝에 `/` 없이)
   - **만들기** → 나오는 **클라이언트 ID**(`…apps.googleusercontent.com`)를 복사합니다.
   - 클라이언트 보안 비밀(Client Secret)은 쓰지 않습니다. 어디에도 넣지 마세요.
5. Railway **Variables**에 `GOOGLE_CLIENT_ID` = 복사한 값으로 저장합니다. 자동 재배포 후 **Google로 로그인**이 동작합니다.
6. (Gmail 피드백 발송을 쓸 때) **API 및 서비스 → 라이브러리 → Gmail API → 사용**,
   OAuth 동의 화면의 **데이터 액세스(범위)** 에 `https://www.googleapis.com/auth/gmail.send`를 추가합니다.

### AI(Claude)에게 도움받기
아래 문장을 그대로 붙여 넣고, 막히는 화면을 캡처해서 함께 보내면 단계별로 안내를 받을 수 있습니다.

```
Google Cloud Console에서 웹 애플리케이션용 OAuth 클라이언트 ID를 만들고 있어.
승인된 JavaScript 원본은 http://localhost:5173 과 https://(내 Railway 주소) 야.
지금 화면을 캡처해서 보낼게. 다음에 무엇을 눌러야 하는지 한 단계씩 알려줘.
```

## 4. 처음 사용하는 순서

1. 관리자: 오른쪽 위 **관리자** 아이콘 → 로그인 → **회원 현황** 팝업이 열립니다.
2. 학습자: **Google로 로그인** → 회원정보(성명·대학·학과·학년·학번·이메일·휴대폰 번호) 입력 → 승인 대기 화면.
3. 관리자: **회원 현황**에서 **승인**을 누르면, 학습자 화면이 15초 안에 자동으로 열립니다. (또는 ‘승인 여부 다시 확인’)
4. 2~15주차 영상 연결: 관리자 메뉴 **강의자료 만들기**에서 해당 주차 강의자료를 열고 YouTube 주소와 학습 구간을 넣은 뒤, 원문 시간을 맞추고 저장합니다.
